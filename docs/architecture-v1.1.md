# 每日 AI 新闻助手 Agent 架构设计 v1.1

日期：2026-10-10　技术路线：Java 17、Spring Boot 3.5、SQLite、DeepSeek Tool Calls

本设计用于指导本地单实例项目的实现和验收。系统根据订阅偏好每日检索新闻、生成有来源的中文简报，保存站内历史，并按配置发送邮件。模型决定工具调用顺序；服务端控制授权、资源、发布和投递。设计与数据库约束样例已经整理，应用代码及真实服务联调仍需实施。

## 1 需求与范围

保留 v1.0 的需求：独立订阅、身份与话题偏好、排除词、时区调度、至少五个基础工具、模型自主选择工具、中文页面、运行轨迹和历史、环境变量密钥、Maven 启动及离线演示。首版默认监听 `127.0.0.1:8080`，一个订阅对应一组访问令牌和独立数据。

基础工具 `list_dir/read_file/search_content/write_file/bash` 保留；新闻工具 `fetch_rss/search_news/fetch_article/get_history/publish_brief` 保留。运行中不强制调用全部工具，也不将检索、阅读、写作固定成流水线。

首版不新增 Redis、独立消息队列、向量数据库、多 Agent 或正式账户系统。公网访问和多实例部署须另行设计身份认证与任务协调。

### 1.1 验收目标

|目标|可验收行为|
|---|---|
|自主决策|不同模型工具顺序、多次检索、工具错误后改用其他来源均能运行|
|结果可靠|只有有效候选且模型正常结束才保存简报；普通文本不能替代提交|
|权限隔离|令牌绑定订阅；任务、简报、轨迹和投递查询均检查归属|
|资源有界|轮次、调用次数、时间、上下文、网络字节、工作区容量均有上限|
|来源可查|服务端补齐标题、链接、媒体与发布时间；模型只引用本次来源 ID|
|恢复明确|重启后旧活动任务失败，已提交简报保留，未投递邮件可恢复处理|
|演示诚实|合成新闻和脚本模型明确标记；演示数据不混入真实模式历史|

## 2 架构与职责

采用单进程模块化应用。HTTP 层处理认证与订阅；调度器创建任务；有界线程池运行 Agent；工具层隔离文件与网络访问；校验器决定候选是否合法；提交服务以一个 SQLite 事务保存简报、成功状态和邮件投递记录；独立投递器消费记录。

[四张设计图](diagrams.md)提供总体架构、执行时序、数据库关系与状态机；`diagrams.html` 提供可直接查看的图形版。

|模块|职责|不得承担的职责|
|---|---|---|
|SubscriptionService|订阅、令牌哈希、偏好版本|以昵称认证|
|RunService / DailyScheduler|创建、领取、并发控制和恢复|在调度线程执行模型或网络调用|
|AgentRunner|维护消息、模型轮次、工具回传和结束判定|绕过工具权限或直接发送邮件|
|LlmClient|DeepSeek 协议、期限、有限重试、usage|选择业务来源或用户范围|
|ToolRegistry / PermissionChecker / ToolExecutor|schema、授权、预算、执行和审计|相信模型提供的用户 ID 或磁盘路径|
|SourceRegistry / NewsClient|本次来源索引、安全抓取和正文缓存|任意 URL 访问|
|BriefValidator / BriefCommitService|约束、最终复检、原子提交|声称来源校验能证明摘要完全真实|
|DeliveryDispatcher|固定收件人、邮件尝试与状态|改变生成成功状态|
|EventService / ArtifactStore|有界事件、脱敏对象、到期清理|无限保存正文或模型内部思考|

Spring Boot 3.5 的 Java 基线见[官方系统要求](https://docs.spring.io/spring-boot/3.5/system-requirements.html)。实现时锁定补丁版本及依赖版本，不使用浮动版本。

DeepSeek 工具调用需要应用执行函数并回传对应 `tool_call_id`，见[官方 Tool Calls 文档](https://api-docs.deepseek.com/guides/tool_calls/)。模型名称通过 `LLM_MODEL` 配置；首版使用非思考模式，思考模式需要独立协议适配与测试，不能将供应商所需协议字段直接暴露在页面或日志中。

## 3 Agent Runtime

### 3.1 创建与快照

认证层从令牌确定 `subscription_id`。任务创建时冻结偏好、推送渠道和邮箱、运行模式、时间窗口、模型配置、提示词版本、工具 schema 版本与限额。数据库是偏好和历史的唯一事实来源；工作区文件只是本次运行的投影。

`ToolContext` 由服务端创建，包含 `runId`、`subscriptionId`、不可变快照、来源注册表、工作区服务、预算与截止时间。模型参数不包含用户范围、邮箱、存储根目录、模型地址或密钥。

### 3.2 决策循环

1. 初始化可信 system 指令和工具 schema；订阅资料作为数据，外部新闻始终作为 tool 数据。
2. 轮次开始前检查状态、截止时间和预算，预留本次模型输入与最大输出额度。
3. 请求模型；先保留完整 assistant 工具请求，再按其顺序逐个执行。
4. 工具执行先检查注册名、参数、归属、允许动作与剩余预算。成功或可处理错误都以匹配的 `tool_call_id` 回传。
5. `publish_brief` 校验并登记候选版本，返回“候选已接受，尚未正式发布”。重复调用可更新候选；失败提交不产生新候选，已接受候选仍可保留。
6. 模型以合法的正常结束信号且没有工具请求结束：存在有效候选则最终复检并提交；否则 `NO_VALID_CANDIDATE`。
7. 截断响应、格式破坏、无预算、超时或被取消均失败；不能因为先前存在候选就报告成功。

模型正常结束与业务提交的契约保留原设计。`publish_brief` 名称为兼容需求保留；工具说明、回传信息和页面须明确“候选提交”语义，避免将它误认为直接发邮件。最后一次接受的候选为待发布版本。

如果一轮要求的工具数超出剩余额度，拒绝该整批并结束为 `BUDGET_EXCEEDED`，避免执行半批后把不完整协议送入下一轮。工具执行期间到达全局期限则直接终止运行，记录未执行调用，不再请求模型。

### 3.3 状态与阶段

任务业务状态只使用 `QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLED`。`phase` 是运行中的可观测阶段：`PREPARING/THINKING/WAITING_TOOL/VALIDATING/COMMITTING`。阶段不进入同订阅活动任务唯一索引的判断，避免新增阶段后漏掉并发约束。

终态不可被旧线程覆盖。领任务使用条件更新 `QUEUED → RUNNING`，所有提交操作再次检查状态、运行期限和取消标记；取消与提交由短事务串行裁决，哪个先完成决定结果。任务达到成功后不再回退为失败。

### 3.4 资源预算

以下均为首版建议默认值，需要在实现与真实联调中校准，不是压测结果。

|资源|默认上限|计算与处理|
|---|---|---|
|模型决策轮次|16|有新决策才加轮次；网络重试仍耗时并计请求数|
|工具请求|40|未知工具及拒绝请求也计数，避免反复试探|
|运行期限|300 秒|单次超时取配置值与剩余时间的较小值|
|模型单次请求|60 秒|最多 3 次总尝试；只重试网络、429 和部分 5xx|
|新闻单次请求|20 秒、2 MiB|流式限制，解压后也限制；最多 3 跳经复检的重定向|
|运行累计网络量|20 MiB|正文与 RSS 共享预算|
|模型上下文|每次估计输入 24000 token|保留 system、工具协议与当前候选；正文由分段读取提供|
|运行 token 预算|累计预留 100000 token|调用前预留输入和最大输出；usage 回填，未知则不释放预留|
|并发与排队|运行 2、待运行 32|数据库记录为准；队列满时调度不占当天领取键|
|来源候选|100 个|超出时工具返回明确截断标记|
|工作区|10 MiB / run|包括正文、草稿、笔记；达到限额拒绝新增写入|

token 估计采用经校准的保守方法，并设置字节上限作为补充；未知 tokenizer 不得宣称准确硬限制供应商计费。超长正文保留抓取与正文截断标记，模型通过 `read_file` 分段读取。不得静默删掉 assistant/tool 配对；上下文仍超限时失败为 `CONTEXT_BUDGET_EXCEEDED`。

## 4 工具与权限

权限由 Java 实施，首版固定注册以下十个工具。额外未知字段一律拒绝，所有字符串与数组有长度上限。

|工具|允许参数|授权与效果|
|---|---|---|
|list_dir|path|仅本次工作区的虚拟路径，有界目录列表|
|read_file|path, offset, max_chars|只读快照、来源、正文、历史与草稿；分段上限 8000 字|
|search_content|keyword, dir, limit|仅本次正文、历史摘要、草稿；最多 20 条命中|
|write_file|path, content|只允许 notes/ 与 drafts/；单文件 64 KiB；不发布|
|bash|command|只接受精确字面值 `pwd`、`ls`；由 Java 返回虚拟路径或目录列表|
|fetch_rss|url|须通过管理员维护的新闻域名与网络策略，注册 source_id|
|search_news|query|使用服务端配置 provider；不允许指定 API 地址|
|fetch_article|source_id|仅本次来源；安全抓取后保存正文，返回 excerpt 与虚拟路径|
|get_history|无|当前订阅、相同模式、最近 30 份简报的有界摘要|
|publish_brief|title, intro, items|校验来源和内容，保存内存候选，不执行外部投递|

`bash` 是兼容工具名的固定只读命令适配器，不启动 shell，不支持参数、管道、重定向、变量展开或拼接命令。若后续验收明确要求真实 shell，应另外设计隔离执行环境；本方案不将兼容适配器宣称为任意 shell 能力。

统一反馈包含 `ok/error_code/message/retryable/data/truncated`。模型可以处理来源超时、空结果和候选校验失败；身份越界、路径越界和禁止动作记录安全拒绝。网络策略不能由模型通过修改参数或工作区文件调整。

### 4.1 工作区

```text
data/
  app.db
  workspaces/{runId}/
    context.json           # 本次偏好与时间窗口，脱敏，不含邮箱与密钥
    sources.json           # 服务端维护，只读
    history.json           # 当前订阅与当前模式的历史摘要，只读
    articles/{sourceId}.txt # 正文，服务端生成，只读
    drafts/                # 模型可写的草稿
    notes/                 # 模型可写的笔记
  artifacts/{runId}/        # 审计详情，模型文件工具不可访问
```

不另建长期用户文件副本；历史、快照和订阅都通过数据库访问。`sources.json` 由抓取服务更新，`fetch_article` 的正文形成 `read_file/search_content` 的实际语料。

文件 API 使用虚拟相对路径，禁止绝对路径、盘符、UNC、`..`、符号链接和 Windows junction/reparse point。父目录与已存在文件都须检查；写文件使用服务控制的目录和原子替换。首版安全范围为通过工具发起的访问，不承诺防御已控制运行账户并能并发改写目录的本机攻击者。

### 4.2 网络与提示注入

`source_id` 解决来源归属与模型凭空编造链接，不能单独防住 RSS 内的恶意链接、重定向或 DNS 重绑定。网络策略须覆盖每个抓取工具：只允许 HTTP(S) 与配置端口、拒绝 URL 用户信息、严格域名白名单、校验全部 A/AAAA 地址、拒绝私网和其他非公网地址、关闭自动重定向并逐跳复检。

推荐使用能够将连接绑定到已校验 IP 的 HTTP 传输实现，并保留原域名的 Host、TLS SNI 与证书校验；否则通过等效的受控出站代理限制连接目标。仅抓取前查一次 DNS 不满足验收。该设计依据[OWASP SSRF 防护指南](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)的域名、IP 与重定向防护原则。

RSS、正文、用户偏好、历史及笔记都视为资料；其中要求改指令、读密钥或修改收件人的内容不获得授权。正文以纯文本呈现，模型参数仍受执行层检查。结构化提示、最小工具权限与脱敏审计参考[OWASP 提示注入防护指南](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)。内容过滤只是辅助，不能保证消除提示注入或摘要失实。

## 5 数据与生命周期

### 5.1 归属模型

首版的身份主体是订阅，统一使用 `subscription_id → subscriptions.id`。只有引入正式账户后才新增 `users`，并让一个用户拥有多个订阅；不得把用户 ID 与订阅 ID 混用。

|表|关系与关键约束|
|---|---|
|subscriptions|token_hash 唯一；profile 为有界 JSON；可停用但默认不硬删除|
|runs|subscription_id 外键；偏好、投递与配置快照；单订阅最多一条活动任务|
|run_sources|复合主键 `(run_id, source_id)`；保存规范 URL、发布时间、excerpt 与正文引用|
|events|run_id 外键；step_id 关联起止；按 seq 排序；summary 和详情大小有界|
|briefs|run_id 唯一；复合外键确保与运行的订阅和模式一致；items 保存完整来源元数据|
|deliveries|brief_id 与 channel 唯一；收件人快照、尝试次数与独立投递状态|

模型提交的 source_id 必须在本次 `run_sources` 中存在。首版简报 items 保留 JSON，不为全站搜索提前拆条目表；BriefValidator 与提交服务负责逐条来源校验，SQL 样例不承诺自动约束 JSON 内每条引用。

SQLite 外键必须在每个数据库连接建立后启用，并在事务外验证；迁移声明外键才能真正形成引用关系，见[SQLite 外键文档](https://www.sqlite.org/foreignkeys.html)。连接同时设置忙等待超时。推荐 WAL 和本机磁盘；WAL 仍只有一个并发写者，见[SQLite WAL 文档](https://www.sqlite.org/wal.html)。任何模型或 SMTP 调用都不能占住数据库写事务。

### 5.2 事件与对象存储

事件记录有界 metadata：`seq/event_type/step_id/tool_name/status/duration_ms/error_code/summary/payload_bytes/payload_inline/payload_ref/payload_state`。不另建内容重复的 agent_steps 表；开始和结束事件使用同一 step_id，UI 组装步骤。

建议事件摘要 512 字符，inline JSON 最大 4 KiB，单份脱敏详情最大 64 KiB，每 run 外置审计详情合计最大 2 MiB，事件数最多 256，数据库 metadata 合计最多 256 KiB / run。超出后存摘要与省略标记，预留最终状态事件额度。字节上限按 UTF-8 编码后计算，不能用字符数量代替。

`payload_ref` 是 ArtifactStore 生成的相对对象键；模型不能写入该键。详情先脱敏并在临时文件写入、校验哈希、原子 rename 成不可变对象，再短事务登记引用。文件先成功而事务失败时产生孤儿文件，后台在 24 小时宽限后删除；数据库引用不得先指向尚未完成的文件。缺失对象通过完整性巡检标记，不将历史页面读取失败伪装为无详情。

到期删除先把引用标记 `EXPIRED` 并清空 ref，再删除文件；中途崩溃由清理器继续。移出 SQLite 只改变存储位置，不能替代配额和保留期。

### 5.3 保留期与删除

|数据|建议保留|到期行为|
|---|---|---|
|工作区正文、草稿、笔记|终态后 7 天|标记正文引用过期后清理目录；活动任务跳过|
|外置审计详情|30 天|引用状态 EXPIRED；页面仍显示摘要|
|事件与运行元数据|90 天|按外键顺序批量清理|
|简报与投递记录|180 天|用户可提前删除；简报保留期间其运行外壳保留|
|来源元数据|随运行外壳|去除正文引用，保留可追溯信息|
|订阅与令牌哈希|停用后保留|用户明确删除时按受控顺序清除关联对象与记录|

用 RESTRICT 防止误删订阅导致审计和历史自动消失。专用清理服务依次清理投递、简报、事件、来源、运行、订阅及文件；不存在“一律 ON DELETE CASCADE”。被保留的重试任务通过 retry_of 引用旧任务，因此其祖先运行外壳也须保留；清理完整重试链时从子任务向祖先删除。备份使用 SQLite 一致性备份接口，并包含 manifest 与外置对象；不要只复制正在使用的 app.db 而漏掉 WAL。恢复验收须覆盖引用缺失、数据库完整性和订阅隔离。

## 6 新闻校验与提交

时间窗口固定为任务创建时的 `[window_end - lookback_hours, window_end]`，不因运行耗时不断移动。未知发布时间、未来时间、窗口外新闻不进入最新新闻候选；抓取时间不能替代发布时间。发布时间与 UTC 时间均用明确单位记录，订阅调度日期单独使用用户时区。

简报 items 只允许 `source_id/summary/why_it_matters`；服务端补齐标题、URL、来源、发布时间和正文截断状态。限制条数、字段长度与简报总字节；当前条目和相同模式最近 30 份简报按规范 URL 去重。规范化仅删除明确的跟踪参数，保留影响资源身份的 query。排除词检查覆盖来源标题、excerpt、已提取正文及生成的标题、导语、摘要与意义说明；正文未读取的情况必须记录证据范围。

空简报允许成功，但必须提供“有效新闻不足”等明确说明，并记录 `empty_brief=true`；不能与抓取全面失败混为一谈。所有来源都不可用时默认失败为 `NO_USABLE_SOURCE`，有可用来源但未找到合规新闻时才允许空简报。来源可追溯与发布时间合规不等于摘要事实已经核验；事实质量通过离线样例和人工抽检评估。

提交事务：再次确认 run 是 RUNNING 且未过期，复检候选，插入 briefs，按快照插入可选邮件 deliveries，再将 run 改为 SUCCEEDED。任何一步失败全部回滚。站内收件箱就是 briefs；不需要一条站内发送任务。唯一 run_id 防止同次运行重复入库。事务成功后通知投递器仅作加速提示，投递器仍定期扫描数据库，因此进程在提示前退出不会丢邮件任务。

## 7 调度与可靠投递

### 7.1 调度

每 20 秒扫描启用订阅。使用 IANA 时区计算当地日期和设定时刻；当天到期、没有活动任务、有排队容量时，在短事务中领取。唯一索引 `(subscription_id, schedule_date)` 防止重复扫描领取同一天，活动任务索引防止手动与定时并发。队列容量校验和插入在同一串行写事务内完成，不以不可靠的内存计数作为唯一依据。

启动晚于当天设定时刻则补领当天；不补历史所有日期。DST 跳过的本地时间顺延到当天下一有效时刻，重复时刻选首次且每日键只领取一次。固定 Clock 编写时区测试。失败当天记录保留，用户手动重试生成新 run，`retry_of` 指向旧 run，`schedule_date` 为空。

任务创建接受可选 `Idempotency-Key`：以订阅与 key 唯一，保存请求哈希。同 key 同内容返回既有 run，同 key 不同内容返回 409。当前任务失败后的真正重试使用新 key；请求重放不触发第二次运行。

首版重启恢复保留 v1.0 的可解释策略：确认旧进程已退出且获得单实例应用锁后，将旧 QUEUED/RUNNING 标为 FAILED，错误 `PROCESS_RESTARTED`；不从工具中间步骤恢复。尚未领取的定时任务按当天规则创建。已提交简报和 PENDING 邮件记录不受影响。限制多实例启动，后续多 worker 才引入租约与 fencing token。

### 7.2 邮件状态

`PENDING → SENDING → SENT/FAILED/UNKNOWN`。投递器通过条件更新领取，先提交状态再进行 SMTP；不在数据库事务中等待 SMTP。确定的临时拒绝可有限重试，永久拒绝等待用户修复；总共最多 3 次尝试，使用 next_attempt_at 与受控退避。失败状态人工重试须经过归属校验、冷却和条件更新，并明确开始新的尝试周期。

`UNKNOWN` 表示 SMTP 超时或断线时不能确定远端是否已经接受；重启后遗留 SENDING 同样进入 UNKNOWN，不自动重发，页面提示可能重复并允许用户明确选择重试。Message-ID 稳定关联 brief ID 便于排查，不是接收方去重保证。系统只保证站内原子提交和投递记录幂等，不承诺 SMTP 恰好一次。

邮件收件人由任务创建时的订阅快照提供，模型无法指定。用户修改邮箱影响新任务，旧任务使用原快照；页面展示待投递地址，可取消未发送任务。离线演示只保存站内，绝不创建外部邮件任务。实际发送能力在有效 SMTP 配置下验收。

## 8 API 与可观测性

保留原 API：订阅创建、`/api/me`、任务创建与历史、任务详情与事件、简报详情与历史、邮件重试。新增投递详情和取消待投递的接口可在 M4 实施。认证之后所有 Repository 查询都带 `subscription_id` 条件，不依赖先查对象再在 Controller 临时比较。

404 同时用于不存在和不属于当前订阅；401 未认证，400 参数不合规，409 活动任务或幂等冲突，429 队列满，503 真实模式配置缺失。异步生成返回 202 与 run ID；前端每 2 秒轮询终态后停止。正文和模型内容均以文本渲染，来源链接限制 HTTP(S)，不执行外部 HTML。

Trace 显示阶段、工具名、脱敏参数摘要、结果摘要、错误码、耗时、模型使用量和来源。认证令牌、邮箱完整值、SMTP 密码、API key 以及模型内部思考不得进入对用户开放的日志。审计文件访问同样检查运行归属，不能把磁盘路径当作 API 下载地址。

|指标|定义与限制|
|---|---|
|生成成功率|SUCCEEDED / 已终结且非 CANCELLED 的运行；demo 与 live 分开|
|工具成功率|ok=true 的尝试 / 已完成工具尝试；策略拒绝单列，不隐藏|
|运行时延|started_at 至 finished_at；排队时延单列；报告 p50/p95|
|模型消耗|所有尝试的已知 usage 累计；未知与预留值单列|
|来源覆盖|每份非空简报的不同域名数，按模式统计|
|重复率|离线样例中的重复事件条目 / 条目数；标注人工或规则判定|
|事实支持率|人工核验可追溯事实中来源支持的事实数 / 核验事实总数|
|投递成功率|SENT / 已终结邮件任务；UNKNOWN 单列|

首版记录指标并在页面提供摘要；不因缺乏现成基准而承诺成功率或性能数值。用户点击率待实现透明的点击统计后再加入，不能把没有采集的数据列为已具备指标。
