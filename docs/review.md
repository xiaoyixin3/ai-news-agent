# 每日 AI 新闻助手 Agent 架构评审记录

评审日期：2026-10-10。依据为原始架构设计 v1.0 和上一轮对话中的 v1.1 建议。以下是文档层面的缺口与修订结论，不是对现有代码缺陷的断言。

## 已保留的正确设计

单实例 Java 应用、DeepSeek 自主工具顺序、服务端 ToolContext 注入范围、仅使用本次 source_id 读取正文、任务偏好快照、模型自然结束后才正式发布、邮件失败不改变生成成功、演示与真实模式区分，均予以保留。

|---|---|---|---|---|

## 五个需要讲清的设计取舍

1. **主体选择**：原系统是独立订阅，不是一个已有的用户平台。重命名 subscription_id 足以修复歧义；账户表是后续能力。
2. **工具保留**：原始需求明确列出五个基础工具，因此不直接删掉它们。bash 用固定只读命令适配，实际 shell 执行须另设隔离环境。
3. **发布契约**：publish_brief 只是候选提交，模型正常结束才正式发布。既避免推翻原流程，也明确了“候选已接受”与“简报已入库”的区别。
4. **恢复范围**：首版重启后旧活动 run 失败，不做模型上下文和外部工具中间恢复；可靠恢复优先覆盖已提交简报和投递记录。
5. **存储边界**：外置 payload 不是容量治理的完成条件。配额、保留期、引用原子性、脱敏和备份同时落实才有意义。

## 评审判断

本项目适合以单实例、受约束的 Agent Runtime 作为首版。先解决权限、资源、归属、提交与恢复，再完善轨迹页面和离线质量评估。不需要为了展示架构而提前引入多 Agent、向量数据库或独立队列。

本轮交付为修订设计、图和建表样例。涉及生产 HTTP 传输、供应商协议、线程中断和 SMTP 行为的结论，需要由工程实现及对应故障测试证实。
